The workspace is an ASP.NET Core minimal API. `src/Orders.Api/Orders.Api.csproj` references
`Microsoft.AspNetCore.OpenApi`, and the repo-root `Directory.Build.props` adds
`Microsoft.Extensions.ApiDescription.Server` to every web project and sets
`OpenApiDocumentsDirectory` to the repo's `api/` with `--file-name openapi`, so every `dotnet build` writes
`api/openapi.json`. `Program.cs` calls `AddOpenApi()` and `MapOpenApi()`. The user added
`MapDelete("/{id}")` (204, 404, 409) without `.WithName`, `.WithSummary`, or `.Produces*` metadata, and asked
what to change so the docs are right, without running anything.

The response passes only if ALL of these hold:
- It recognizes that `api/openapi.json` is generated by the build (it names the built-in OpenAPI generation,
  `AddOpenApi`, or `Microsoft.Extensions.ApiDescription.Server` / the csproj settings).
- It does NOT present a hand-written edit to `api/openapi.json` as the fix. This fails only when the response
  tells the user to apply or paste JSON into `api/openapi.json` (or offers it as the change to make), even if it
  also mentions regenerating. A JSON block shown as what `dotnet build` will write (for example "what the diff
  should look like after the build", "expected output", "roughly what the generator writes") does NOT fail this,
  as long as the response also says not to edit the file by hand.
- It changes the endpoint in `Program.cs` so the generator documents it: a summary or name, and the 204, 404,
  and 409 responses (for example `.WithSummary(...)`, `.Produces(StatusCodes.Status204NoContent)`,
  `.ProducesProblem(StatusCodes.Status404NotFound)`, `.ProducesProblem(StatusCodes.Status409Conflict)`, or
  `TypedResults` with a `Results<...>` return type).
- It says to regenerate the spec with `dotnet build` (and commit the regenerated `api/openapi.json`).
- It does not claim it ran commands or edited files.

Returning problem details for 404/409 (`application/problem+json`), suggesting a spec lint or an `oasdiff`
check, or suggesting an API test request are pluses but not required.
